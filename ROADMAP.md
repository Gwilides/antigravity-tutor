# План Реализации Проекта (Implementation Roadmap)

> Этот документ является пошаговой инструкцией для разработки и развёртывания системы **Antigravity Tutor** в новом контекстном окне агента.

---

## 1. Контекст и Обзор Проекта

* **Назначение:** Создание полноценной автономной системы глубокого обучения для **Google Antigravity** с постоянным графом знаний в Obsidian.
* **Базовая концепция:** Подробно описана в [`CONCEPT.md`](./CONCEPT.md) (двухуровневое хранилище `sessions/` vs `knowledge/`, тезисы Матушака в заголовках, цепочка Амоса внутри карточек, ритм «One reasoning step at a time», KST-фронтиры, умное повторение `/refresh` без Review Hell).
* **Стек технологий:**
  - Нативные механизмы Antigravity (Skills, Rules, Subagents, диалоговые окна `ask_question`, Mermaid, KaTeX).
  - Python 3 (`pyyaml>=6.0` для надёжного парсинга YAML frontmatter и шаблонов).
  - Декларативные семантические инструкции в промптах («дописать в конец файла», «обновить статус в шапке») без жёсткой привязки к внутренним именам инструментов.
* **Языковой стандарт (Language Convention):**
  - Все файлы самого репозитория (системные правила `GEMINI.md`, навыки `SKILL.md`, код `graph.py`, docstrings, шаблоны, `config.example.json` и `README.md`) пишутся **строго на английском языке**.
  - Интерфейс обучения (сократический диалог, квизы, текст заметок в `sessions/` и карточек в `knowledge/`) **динамически зеркалирует язык общения пользователя** без принудительных дефолтов.

### Задача 2: Разработка педагогического навыка `teach` (`.agents/skills/teach/SKILL.md`)
* [ ] Использовать эталонный первоисточник Амоса из [`references/teach_skill_reference.md`](./references/teach_skill_reference.md).
* [ ] Создать фронтматтер навыка (`name: teach`, `description: ...`).
* [ ] Описать полный 5-фазный цикл обучения:
  * **Фаза 0 (Resume & Recall):**
    - Проверка незавершённых сессий (`status: in_progress` или `paused`) и предложение продолжить с места остановки.
    - Проверка устойчивости непосредственной базы: 1 глубокий концептуальный вопрос по каждому непосредственному родителю из *Inner Fringe*. Если ответ вызывает легкое сомнение — 1 контрольный микро-вопрос.
    - **Branching Protocol:** При обнаружении пробела в пререквизите — карточка помечается `status: shaky`, и ученику предлагается развилка через диалоговое окно (10-минутное ответвление для закрытия базы либо понятная практическая аналогия).
  * **Фаза 1 (Adaptive Probe):**
    - *Cold Start (новый домен):* 3–5 адаптивных калибровочных вопросов (бинарный поиск уровня сложности) через диалоговое окно с параллельными вариантами ответов и обязательным пунктом `"I don't know"` последним. При первом сигнале пробела опрос останавливается — потолок найден.
    - *Warm Start (известный домен):* Бинарный поиск пропускается (база уже проверена в Фазе 0); задаётся только 1 неоцениваемый вопрос *Goal Mode* для выявления конкретной практической цели ученика.
  * **Фаза 2 (Plan & Orient):**
    - Вызов субагента `research` для проверки определений и фактов (при необходимости).
    - Генерация локального Mermaid DAG урока в чате для ориентации ученика.
    - **Без блокирующей паузы на одобрение:** агент не ждёт подтверждения плана, а сразу приступает к Шагу 1, устраняя лишнее трение.
  * **Фаза 3 (Teach Loop — «One reasoning step at a time»):**
    - *Квант вывода:* Объяснение одного шага рассуждения (мотивация проблемы $\to$ механизм решения).
    - *Live Mirror:* Дозапись шага в файл сессии Obsidian.
    - *Квиз-метроном:* Интерактивный проверочный вопрос по шагу (4 варианта + `"I don't know"`).
    - *Педагогическое правило при ошибке или «I don't know»:* Агент **никогда не выдаёт готовый ответ** и не пропускает шаг. Он объясняет суть с альтернативной точки зрения / через бытовую аналогию, дробит квант на более простые части и даёт альтернативный проверочный вопрос.
    - *Инкрементальная карточка:* Сохранение карточки концепта в `knowledge/<domain>/<slug>.md` сразу после прохождения узла (ID карточки равен чистому файловому слагу `id: <slug>`).
    - *Практический FIRe 1-го порядка:* При сохранении карточки концепта $B$ агент автоматически обновляет дату `last_tested: <today>` у всех его непосредственных родителей из `depends_on`.
  * **Фаза 4 (Complete & Sync):**
    - Автоматический перевод сессии в `status: completed` (обновление метаданных в начале заметки) сразу после кристаллизации финального целевого концепта.
    - Опциональная рефлексия: предложение сформулировать суть урока в одном предложении (без блокировки завершения).
    - Запуск `python3 scripts/graph.py sync --domain <domain>`.

### Задача 4: Разработка движка графа (`scripts/graph.py`)
* [ ] Написать CLI-скрипт на Python 3 с использованием `pyyaml>=6.0`:
  * **Безопасная работа с файловой системой:**
    - Читать путь к хранилищу из `config.json` (с флагом `--vault <path>`) с обязательным раскрытием тильды `~` (`os.path.expanduser()`).
    - Игнорировать служебные директории Obsidian (`.obsidian/`, `.trash/`, `.git/`).
    - При холодном старте (папка домена или `_index.md` ещё отсутствуют) автоматически создавать директорию домена, инициализировать `_index.md` из `domain_index.template.md` без падения с `FileNotFoundError`.
  * **Нормализация связей:**
    - При парсинге `depends_on` удалять любые вики-скобки, кавычки и пробелы (`re.sub(r'[\[\]"\'\s]', '', item)`), поддерживая как `[[slug]]`, так и чистый `slug`.
    - Обработка висячих ссылок (Dangling dependencies): если карточка ещё не создана на диске, считать её виртуальным узлом `(Locked)` с предупреждением в stderr без падения скрипта.
  * `python3 scripts/graph.py sync [--domain <d>]`:
    - Сканирование frontmatter карточек в `<vault_path>/knowledge/`.
    - Регистронезависимый поиск секции с `Planned Curriculum` в `_index.md` для корректного отображения открытого фронтира (`[Ready]` vs `[Locked]`) без создания файлов-призраков.
    - Проверка графа на циклы (алгоритм Тарьяна/DFS). При обнаружении цикла — вывести точную цепочку в stderr (`[ERROR] Dependency cycle: A -> B -> A`) и завершиться с кодом `sys.exit(1)` **до записи в `_index.md`**.
    - Расчёт фронтира (Inner Fringe, Outer Fringe, Locked).
    - Генерация компактного горизонта Mermaid (до 10–15 узлов) с чистым синтаксисом лейблов строго между маркерами `<!-- AUTO-GENERATED HORIZON START -->` и `<!-- AUTO-GENERATED HORIZON END -->`. Если маркеры отсутствуют — дописать их в конец файла, не затирая существующие строки.
  * `python3 scripts/graph.py refresh [--domain <d>]`:
    - Отбор карточек для сессии `/refresh` (жесткий лимит: 3–5 карточек).
    - Формула вероятности вспоминания: $R = 2^{-\frac{\Delta t}{I}}$ (где $\Delta t$ — число дней с `last_tested`, $I$ — `interval_days`).
    - Приоритет узлов из окна $0.4 \le R \le 0.6$ с весом «хаба» (число входящих зависимостей от других карточек).
    - Протокол мягкой посадки при общем перерыве более 30–45 дней (1–2 макро-вопроса).
    - Прогрессия интервалов: при успехе (`Solid`) $I \in [3 \to 7 \to 16 \to 35 \to 90]$ (или $I_{new} = \text{round}(I \times 2.2)$); при пробеле (`Shaky`) — сброс на $I=1$ день.
  * `python3 scripts/graph.py status` — сводка: количество понятий по доменам, текущий открытый фронтир.
  * `python3 scripts/graph.py new-session --topic <t> [--domain <d>]` — инициализация файла сессии в `<vault_path>/sessions/` на основе шаблона `session.template.md` (`status: in_progress`).
